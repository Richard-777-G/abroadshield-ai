1. EXECUTIVE SUMMARY
================================================================================

AbroadShield AI is an agentic AI web application that walks a single student
through the entire journey of going abroad to study — from the visa decision
to the sponsored job offer. Unlike a chatbot that waits to be asked, the
agent ACTS: it drafts emails, gap-checks documents, tracks deadlines,
shortlists housing, tailors CVs, and runs a networking tracker — all with
the student's one-tap approval.

The application is built as a single-page Next.js 16 experience with a
header-driven view-switching architecture. The landing page (Home) presents
the product vision with a premium AI hero visual; six additional views
(Journey, Agent, Countries, Network & Jobs, Connectors, Pricing) each
present their own bespoke hero, data, images, and interactive features.

KEY METRICS:
- 27 React components (6,535 lines of component code)
- 1,245-line domain data layer (data.ts)
- 421-line custom CSS design system (globals.css)
- 24 AI-generated images (2.8MB total)
- 10 study-abroad countries with full visa rules
- 16 real platform connectors
- 1 functional LLM-powered agent chat (z-ai-web-dev-sdk)
- 7 views (Home + 6 section views)
- 0 lint errors

2. PRODUCT VISION & CORE IDEA
================================================================================

THE PROBLEM:
Every year, millions of students leave home to study abroad, and almost
every one of them ends up doing it alone. A visa consultant helps once,
then disappears. A forum answers one question, then moves on. A government
website assumes you already understand its own rules. Nobody stays with
the student through the whole journey.

THE SOLUTION:
AbroadShield AI is built to be the one thing that does stay. It is a
highly agentic AI — it doesn't wait to be asked. It holds a running,
detailed picture of exactly where a student stands, and takes real action
on their behalf, at every stage of the journey, in every way it practically
can.

THE FOUR PHASES:
1. Pre-Departure — visa checklist, document gap-checking, deadline tracking,
   drafting emails and forms.
2. Arrival — housing search vs budget, landlord & bank messages, FRRO/police
   registration within 14 days.
3. Studying & Part-Time — spending vs runway, work-hour cap compliance,
   academic deadline management.
4. Job Success — scan openings vs post-study visa runway, tailor CV/cover
   letter per role, interview prep, alumni networking tracker.

THE FOUR PILLARS (Why not just use Claude/ChatGPT):
1. Persistent journey memory — organized around a real sequence for one
   specific country.
2. Proactive, not reactive — reaches out first, before a deadline.
3. Country-specific rules baked in — the student never explains from scratch.
4. Agentic task execution — drafts, searches, shortlists, fills in, with
   approval. The strongest pillar.

4. ARCHITECTURE OVERVIEW
================================================================================

The application uses a HEADER-DRIVEN VIEW-SWITCHING architecture instead
of a traditional long-scroll single page:

LAYOUT (layout.tsx):
  <html className="dark">
    <body>
      <FloatingBackground />     ← fixed, full-viewport, -z-10
      <ScrollProgress />         ← fixed, top, z-100
      {children}                 ← the page
      <Toaster />                ← toast notifications
    </body>
  </html>

PAGE (page.tsx):
  <SiteHeader activeView onViewChange views />
  <main>
    <AnimatePresence mode="wait">
      <motion.div key={activeView}>
        {activeView === "home"     → <Hero3D /> + <HomeShowcase />}
        {activeView === "journey"  → <ViewHero /> + Journey sections}
        {activeView === "agent"    → <ViewHero /> + Agent sections}
        {activeView === "countries"→ <ViewHero /> + CountryRules}
        {activeView === "network"  → <ViewHero /> + NetworkingJobs}
        {activeView === "connectors"→<ViewHero /> + Connectors}
        {activeView === "pricing"  → <ViewHero /> + Pillars + Pricing + Vision}
      </motion.div>
    </AnimatePresence>
  </main>
  <SiteFooter />

KEY ARCHITECTURAL DECISIONS:

1. VIEW SWITCHING (not routing):
   - Single page with client-side state (useState) drives view switching.
   - URL hash (#journey, #agent, etc.) provides deep linking.
   - hashchange listener syncs state when the hash changes.
   - AnimatePresence provides smooth cross-fade + slide transitions.
   - Only the active view's sections mount (less DOM, faster).

2. FLOATING BACKGROUND (global, fixed):
   - Rendered once in layout.tsx, behind everything (-z-10).
   - 5 drifting orbs + 14 floating 3D shapes + 2 neural network SVGs +
     rotating conic sweep + animated grid + film grain.
   - Mobile-optimized: fewer shapes on small screens.
   - ssr:false dynamic import to avoid hydration mismatch.

3. SCROLL PROGRESS BAR:
   - Fixed at the very top (z-100), fills as the user scrolls.
   - Uses framer-motion useScroll + useSpring.

4. HEADER AS VIEW SWITCHER:
   - The header nav pills ARE the view switcher (no separate tab bar).
   - Active pill animates with a spring layoutId.
   - Mobile: sliding panel menu.

8. AI/LLM INTEGRATION
================================================================================

ENDPOINT: POST /api/abroadshield/chat
RUNTIME: Node.js (force-dynamic)

SDK: z-ai-web-dev-sdk 0.0.18 (backend-only)

SYSTEM PROMPT (encodes the full product context):
- Student identity: Aarav Mehta, Pune → Manchester, MSc Data Science, Sep 2026.
- Current state: Pre-Departure phase, visa appointment 28 Aug 09:30 IST,
  11/13 docs verified, bank statement missing page 3, passport photo flagged.
- The 4 phases the agent owns (Pre-Departure → Arrival → Studying → Job Success).
- Behavior rules: ACT don't advise, be concise, match the student's register,
  state country rules explicitly, end drafts with "Approve to send?", never
  invent facts, keep under 220 words.
- Output format: Markdown with bold facts, bullet lists, fenced code blocks
  for drafts, "Approve / Edit / Decline" cue.

CONVERSATION HISTORY:
- Carries the last 8 messages for continuity.
- System prompt as the first "assistant" message.

DRAFT DETECTION (client-side):
- isDraftMessage() checks for "Approve to send", "Approve / Edit / Decline",
  "Subject:", "Dear", or fenced code blocks.
- When detected, renders Approve/Edit/Decline action buttons.
- extractDraftMeta() infers kind (email/form/search/document/message),
  title, recipient, detail, and phase from the LLM reply content.
- Actions are pushed to the Zustand approvalsStore → appear in the
  ApprovalsHistory timeline.

14. PERFORMANCE OPTIMIZATIONS
================================================================================

1. VIEW-BASED ARCHITECTURE:
   - Only the active view's sections mount → less DOM, fewer simultaneous
     animations → faster render.

2. MOBILE-OPTIMIZED BACKGROUND:
   - FloatingBackground detects mobile (< 768px) and reduces floating shapes
     from 14 → 6.
   - Skips the heavy conic gradient sweep on mobile.
   - Reduces simultaneous Framer Motion animations.

3. LAZY IMAGE LOADING:
   - All 24 images use loading="lazy" → don't block initial render.

4. SSR-SAFE BACKGROUND:
   - FloatingBackground uses ssr:false dynamic import → avoids hydration
     mismatch from useReducedMotion.
   - Deterministic particle positions (sine-based pseudo-random, not
     Math.random) → no SSR/client mismatch.

5. ANIMATEPRESENCE MODE="WAIT":
   - View transitions use mode="wait" → old view exits before new view
     mounts → no overlapping animations.

6. REDUCED MOTION:
   - Reveal component + FloatingBackground honor prefers-reduced-motion.
   - Renders static when reduced motion is requested.

7. PERSPECTIVE + 3D:
   - CSS transforms (not WebGL) for 3D effects → no GPU-heavy canvas.
   - AIPrimeCore hover-tilt uses lightweight useMotionValue + useSpring.


================================================================================
15. KNOWN LIMITATIONS & RISKS
================================================================================

1. AGENT-BROWSER QA LIMITATION:
   - The Chromium browser (agent-browser) crashes the Next.js Turbopack
     dev server due to system RAM limits.
   - QA is performed via curl (content checks) + lint (code quality) +
     API testing instead of visual browser QA.
   - Recommendation: run visual QA in a higher-memory environment.

2. AUTH NOT WIRED TO BACKEND:
   - AuthModal UI is built (login/signup, social auth buttons) but does
     not persist to a backend. NextAuth.js is installed but not configured.
   - The Prisma User model exists but no auth flow writes to it.

3. APPROVALS STORE IS IN-MEMORY:
   - The Zustand store resets on page refresh. No persistence to
     Prisma/SQLite yet.

4. COUNTRY DATA IS STATIC:
   - All 10 countries' rules are hardcoded in data.ts. In production,
     these should be in a database and updated as rules change.

5. CHAT HISTORY NOT PERSISTED:
   - Conversation history resets on page refresh. The API carries the
     last 8 messages within a session but doesn't persist across sessions.
